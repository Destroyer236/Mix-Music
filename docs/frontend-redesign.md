# LinkLine 前端改版说明

本次改版按用户的 QQ 音乐参考及后续截图，调整推荐页、精选歌单、排行榜、侧栏、播放器、设置页和不同窗口尺寸的布局。
最初视觉草案由 Claude Code 提供；按用户后续要求，目前设计、实现和验证由 Codex 完成，不再调用 Claude。

## 接口与业务保护

项目使用 Electron、Vue 3、TypeScript 和 Less。页面继续通过原有服务、状态管理和 IPC 使用业务能力。
以下目录和契约保持不变：

- `src/main/`、`src/common/`：平台、账号、播放、下载、本地数据库、更新、共享类型及 IPC。
- `src/renderer/ui/services/`、`ui/settings/`：已有业务服务、设置字段及保存契约。
- `src/renderer/core/`、`store/`、`utils/`、`worker/`：播放器、状态、请求和持久化实现。
- `src/renderer/router.ts`、`src/renderer-lyric/`：路由路径与参数、懒加载和桌面歌词通信。
- `package.json`、`package-lock.json`：应用运行依赖和版本。

App、本地音乐、下载页面的脚本保持原样。设置页只增加用于选择分类的前端开关状态，原有设置业务逻辑与交互绑定保留。
精选歌单增加 RadialCategories 分类展示组件，删除被取代的下拉选项与常用标签展示计算；排行榜增加现有 TrackArtwork 展示组件。原有平台、分类、排序、加载、分页、播放与导入交互绑定保持不变。
Shell 调整导航与主区域页面编排；Discover 调用已有目录、榜单、搜索及播放能力组成真实推荐内容。最近播放使用 /list?view=recent，由 Shell 在主区域显示，不新增或改写路由定义。Library 删除重复的内部音乐库侧栏，加入歌单面板删除试听列表选项，音乐库默认与失效选择回到收藏；导入歌单移至工具栏。
PlayerBar 将模式下拉框改成图标按钮，仍调用原有 setTogglePlayMode；保留「下一首」按钮与原有 playNext 调用。新增状态只用于评论、歌曲操作和播放列表面板；歌曲操作组件复用原有收藏、歌单、专辑搜索、剪贴板与倍速能力。
播放、暂停、上一首、下一首、收藏、进度、音质、音量和队列的业务逻辑保留；未修改核心播放接口。

## 推荐页

推荐页以用户最新截图为布局参考，去掉大标题、日期、两张大面积彩色面板和多段重复推荐区域：

1. 顶部只保留简洁问候和「我的喜欢」入口。
2. 第一行左侧为横向「猜你喜欢」卡：淡青黄背景、动态按本地时段的文案、实际歌曲封面与静态唱片造型，绿色按钮播放推荐歌曲。
3. 右侧三张方形封面卡：真实平台精选歌单，以及有收藏时显示的 Favorites。名称、封面和收藏数量均来自实际数据。初次加载时直接在对应卡片位置显示方形封面与两条文字骨架，不在整行下方追加游离的加载区；已有收藏卡继续显示。骨架为静态 CSS，不添加定时器或动画。失败提示与重试也留在原卡片位置。
4. 下方一组歌曲列表，桌面三列、最多九首；小封面、歌名、歌手、播放与喜欢操作。可播放全部、换一批、切换平台和收藏歌手，或进入完整榜单。歌曲标注实际来源平台。跨平台去重使用原有 sameRecording：歌名和歌手归一化、录音版本、时长（差值不超过 3 秒）或缺少时长时的专辑信息；相同 source/id 直接合并，现场与翻唱等不同录音不强行合并。
5. 小窗口将上方封面排成可横向滚动的音乐卡片带，右箭头滚动或换一组真实歌单；歌曲列表改成两列，避免拥挤。

收藏歌手作品来自原有音乐搜索，排除已收藏、重复和不相关歌手。暂时无合适作品时显示真实热播歌曲。
未添加听歌报告、VIP 或“某歌手的听众也在听”等现有接口不支持的功能和统计。

平台名使用现有 sourceNames，统一显示真实平台名称。平台筛选第一项为「全部」，默认选中。全部模式从各支持平台读取真实榜单与收藏歌手作品，在有界候选集合中随机取样并交错排列，每首歌曲保留原始 source 与 id；选择单个平台后仅显示该平台。部分平台失败时继续使用其他平台结果。每一批先收集完可用结果，再一次性发布；刷新期间保留上一批，不按每个响应反复混排。
单平台个性化区域明确说明「从某位歌手再发现一首」，属于基于收藏歌手的轻量发现，不声称使用后台个性化模型。
尚无收藏时，显示如何建立音乐口味的说明，并提供真实平台歌单与热播内容。
各区域独立处理加载、空结果和失败；失败时提供重试或切换平台，不填充虚构歌单、歌曲和播放量。

首页最多保留 8 个歌单、9 首热播歌曲和 9 首歌手作品；页面只显示三张方形音乐卡和一组歌曲列表。歌手偏好仅统计当前收藏列表最后 200 条，最多提供 3 位歌手。
使用浅层状态，切换平台时替换结果；通过请求版本防止旧结果覆盖新平台，离开页面后忽略迟到响应。
全部模式对各平台读取小批结果，前端最多同时处理两个平台任务；12 秒未完成的平台任务不阻塞后续结果。现有 SDK 在途请求可能自然完成，页面离开后忽略结果并清理等待计时器。页面不会轮询或预抓取整个曲库。

问候语使用本地时间：00:00–05:59 / 22:00–23:59「夜深了」、06:00–11:59「早上好」、12:00–13:59「中午好」、14:00–17:59「下午好」、18:00–21:59「晚上好」。只保留一个下次整点更新的 timeout，窗口获得焦点时立即校准，离开页面清理计时器与监听。

## 精选歌单与排行榜

两页使用与推荐页一致的 20px 标题、30px 横向留白、轻量绿色平台选择和 4px 封面圆角。
去掉英文宣传语、夸张的大标题、装饰图标、粗边筛选卡和排行榜的虚构装饰编号。

精选歌单以真实平台封面为主体，桌面五列、较窄桌面四列、800px 以下三列；分类栏显示当前选中的大分区名称和对应语义图标；已筛选的子标签以小标签展示，排序保留在右侧。名称、作者与播放量来自现有接口。
点击分类图标打开环形大分区和详细标签，收起后只保留选中内容；排序仍使用原有选择控件，链接 / ID 导入折叠成一条小入口。
加载时显示与实际网格相同的静态封面和文字骨架；不增加图片或请求。

排行榜使用紧凑榜单标签和完整榜单选择控件，窄窗口标签可横向滚动，选中榜单由第一首真实歌曲封面、标题、实际总数和播放 / 导入操作展示。
下方沿用原有 TrackTable、真实顺序与分页，前三名仅改变序号颜色。没有额外请求榜单图片或引入图表库。
平台、分类、排序、榜单、分页、导入、播放、下载、添加歌曲和失败重试的原有绑定均通过保护检查。

## 侧栏与顶部

- 主导航仅为「推荐、精选歌单、排行榜」；首页只保留顶部搜索，删除「寻找新的声音」和侧栏搜索入口。
- 我的音乐依次为「喜欢、最近播放·真实数量、本地下载」。
- 下方提供「自建歌单 | 收藏歌单」和 + 按钮，复用原有 PlaylistDialog 和 createUserList。
- 自建歌单包含本机及已同步的平台自建歌单；收藏歌单按现有 source/sourceListId 标记分类。试听列表模块、音乐库入口及加入目标已删除。原有播放队列所需的内部列表与数据契约保留，不删除用户歌曲数据。
- 本地下载进入本地音乐页，页内提供「本地音乐 / 下载管理」切换，原有能力保留。
- 顶栏在搜索旁提供齿轮设置、调色盘外观、明暗切换、更新及窗口控制。
- 顶部搜索使用单层圆角容器，输入框自身无边框、内阴影或独立焦点描边，键盘焦点由整个容器的主题色边框与轻描边提示。左侧复用 Lucide 搜索 SVG，右侧清空按钮仅有文字时出现，清空后返回输入框；提交按钮复用 Lucide arrow-right SVG，空白查询禁用，Enter 和按钮均走原有 search 函数与 `/search?text=` 路由。38px 常规高度、800px 以下 34px，高度和图标间距适配小窗口。自定义背景使用有色轻透明底，焦点时增加不透明度以提高阅读清晰度；没有新增依赖、图片或后台任务。
- 顶部 SearchBox 输入联想复用已有 QQ `tipSearch.tipSearch` 的结构化结果，不修改 SDK 或新增后端接口；请求失败时复用原酷我关键词联想。结果清楚分为歌手与歌曲：歌手最多 2 位，使用真实圆形头像与双列布局；歌曲最多 4 首，歌名与演唱者分两行排列。接口提供图片时使用已有 TrackArtwork 按需显示；没有封面时使用已有 Lucide 唱片图标，不逐首发起封面或歌曲详情请求。点击歌手进入原 `/search?type=artist`，点击歌曲使用歌名与演唱者进入原歌曲搜索，普通提交仍保持原行为。关键词 / 历史在相关搜索区显示，总条目最多 8 个。
  面板常规宽度至少 420px，上限为窗口宽度减去边缘留白；歌手头像圆形、歌曲图形为小圆角方形，分区以轻分隔线和小标题区分。行尾箭头仅悬停 / 键盘选择时出现，加载时使用静态骨架；浮动高度不超过 460px，并限制在播放器上方，小窗口内部滚动，底部全部结果入口固定可见。普通 / 图片主题共用原颜色变量，文字以文本节点高亮，不使用 HTML 注入。
  每个输入框独立保存请求对象，避免取消其他调用者的请求；220ms 防抖、3s 截止、过时响应丢弃、去重和最多 20 个关键词的内存缓存。只在聚焦并输入完成时请求，中文输入法组词中暂停，关闭取消定时器和请求，取消后的主请求不会再触发备用请求。支持点击、上下键、Enter、Escape、点击外部关闭；历史复用原设置与保存能力，接口不可用时保留直接搜索入口。没有新增依赖或常驻任务。
- 桌面侧栏为 224px，较窄桌面为 218px；800px 以下为 56px 图标侧栏。
  小窗口固定品牌、功能、歌单分组及创建按钮，只让下方歌单列表滚动，减少整条侧栏上下挤压。
  自建与收藏分组改为有明确名称的图标按钮；各入口保留可访问名称、键盘焦点及提示。

最近播放点击后在右侧主区域切换为完整页面，支持搜索记录，播放后留在当前页面。实际播放记录保存到项目 `data/music-links.json`，最多 500 条，同一列表内同一歌曲去重，重复播放移到最前，超过上限移除最旧记录，重启恢复。内存列表、文件写入和文件恢复共用同一上限；已有文件不需要迁移。每条仅保存歌曲页链接、歌曲与列表 ID、歌名、歌手，不存封面、音频、歌词或账户信息。它独立于会被播放模式清空的 playedList 导航栈；点击记录通过原列表回放，音乐已移除时显示错误。

同一个文件的 favorites 数组保存收藏歌曲的官方页面链接，本地歌曲保存 file URL。原数据库仍负责完整收藏信息和播放数据，链接文件是可查看的引用备份，不是独立恢复整个音乐库的导入文件。首次启动会将现有收藏写入；收藏变化自动更新。启动读取失败或新建空库时保留已有文件，明确移除最后一首收藏后则正常写空。写入串行化并通过临时文件替换，损坏或不支持版本的文件不会被覆盖；文件已加入 Git 忽略规则。

默认路径相对于启动工作目录（项目启动脚本会切换到项目根目录）；QA 使用 LINKLINE_MUSIC_LINKS_FILE 指向隔离目录。保存错误在最近播放页显示。移除 FavoriteSyncNotice 展示后，喜欢依旧调用原有官方收藏流程：向现有已登录且支持同步的平台匹配并操作。此机制本来就支持多平台同步，未改成只限定歌曲来源平台。

## 播放器与图标

- 底部按用户最后提供的播放条截图布局：左侧 52px 方形封面，歌名与歌手同行，下面是喜欢、评论和更多；窄窗口适当缩小封面与文字。
- 中间依次为播放模式图标、上一首、绿色胶囊播放/暂停、下一首和音量；播放模式在列表循环、随机播放、单曲循环、顺序播放四种模式之间切换。保留原有切歌逻辑，播放按钮在最小窗口与最大化时保持居中。
- 右侧依次为音质、桌面歌词和播放列表。音质按钮仅在打开时查询可用音质，保留原有偏好、权限和播放切换逻辑。桌面歌词调用原有开关。
- 当前时间、短进度条、总时长位于控制按钮下方；进度条最长 440px，采用深色已播段、小圆点及浅色底轨。
- 两种已有进度样式均采用当前参考图的布局，播放条统一为 84px。
- 歌曲旁的「更多」改为歌曲操作菜单，包含查看专辑、我喜欢、添加到歌单、分享和倍速滑动条（0.5×–2×，步长 0.05×），在滑动条轨道上的真实 1× 位置标一个与滑块同直径的 10px 圆点；当前为 1× 时圆点显示绿色，下方只显示「1×」，点击可恢复 1 倍速。刻度使用滑条三分之一位置，并按滑块宽度补偿，不错误居中。滑条支持拖动及原生方向键。菜单位于点击的三个点按钮上方 8px，并对齐按钮左侧；靠近窗口边缘时自动限制在可视范围内，点击外部或 Escape 可关闭；位置随窗口尺寸更新，关闭时卸载监听。
- 查看专辑沿用已有专辑搜索，专辑元数据缺失时禁用；播放详情打开时会先收起详情。喜欢复用原有收藏切换；添加歌单复用 TrackActionModal，并保留点选时的歌曲，避免切歌后误加下一首。
- 分享通过原有 SDK 生成平台歌曲页链接并复制到剪贴板，不代替用户发送消息；本地歌曲只复制歌名与歌手，不暴露文件路径。倍速调用原有 window.app_event.setPlaybackRate，沿用播放器的范围校验与保存。
- 播放列表改为右下角的独立轻量面板，显示实际队列、当前歌曲和稍后播放，可点选播放；没有全屏遮罩。面板仅打开期间监听外部点击和窗口变化。
- 播放模式以素材库 SVG 图标依次切换列表循环、随机播放、单曲循环、顺序播放，删除「播放一首」入口，不再显示模式下拉列表。旧设置为 none 时，由前端调用原有 setTogglePlayMode 恢复为 listLoop，设置类型和播放核心接口不变。列表循环采用 [Lucide repeat-2 官方 SVG](https://lucide.dev/icons/repeat-2)，直接使用官方几何素材并复用本地精灵，不自行绘制路径、不增加素材库运行依赖。
- 评论按钮按需复用已有 CommentsPanel 和平台评论接口，不显示虚构评论数。暂不支持评论的平台沿用原有提示。
- 模式、播放、暂停、上一首、下一首、队列、歌词、音质、音量、红心、评论、更多及部分顶部图标采用 [Lucide 官方素材](https://lucide.dev/icons/)。
  SVG 几何保存在 `src/renderer/assets/svgs/lucide-*.svg`，沿用原有 SVG sprite 构建方式，仅根节点呈现属性交给界面控制。
  不引入图标运行库、不使用在线图标 CDN，也不添加 PNG 解码和字体下载。
  完整 ISC/MIT 许可保存在 `src/static/licenses/lucide.txt`，随构建复制到运行包。

## 环形分类与本地下载

## 自定义背景与图片配色

按用户新要求，外观面板第三个主题入口由「跟随系统」改为「自定义」。首次点击通过原有 showSelectDialog IPC 选择 JPG / JPEG、PNG、WebP 或 BMP；已有图片时点击立即恢复自定义主题。新增更换图片、定位背景文件夹、自动 / 浅色 / 深色明暗选择和配色预览。浅色、深色、恢复默认仍可使用，普通主题下原有手动点缀颜色保留。旧 system 偏好仍能读取；新增 custom 与 customTone 仅扩展前端 localStorage 外观记录，原偏好键 lx-modern-appearance-v1 不变。顶部明暗按钮在自定义状态下只切换 customTone，保留图片。

配色调研与实现依据：

- [Material 动态颜色说明](https://github.com/material-foundation/material-color-utilities/blob/main/concepts/dynamic_color_scheme.md)：从图片提取代表色，再分配面板、强调色、文字等颜色角色，通过不同明度形成层次。这里采用同色系低彩度大面板、较高彩度强调色，避免把照片里的高饱和颜色大面积铺到控件上；没有复制 Material 的 HCT 算法或引入组件库。
- [Oklab 作者的颜色空间说明](https://bottosson.github.io/posts/oklab/)：按感知明度、色相与彩度生成协调色。实现使用文中公开的 sRGB / Oklab 变换系数；对低彩度图片保持中性色，不强行添加绿色。64×64 像素样本量化到最多 512 个颜色桶，按占比和有限彩度加权选择代表色，少量亮色斑点不会盖过图片主要色系。
- [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)：普通文本目标至少 4.5:1。自定义主要面板使用 86% 有色底，侧栏 90%；计算文本、次要文本与强调文字在图片全黑和全白两端背景上的对比度，并检查选中态底色。按钮文字在黑白中选择对比更高者。这是颜色角色的约束，不能据此宣称整个应用已完成 WCAG 合规审计。

窗口只使用一张 CSS cover 背景，居中裁剪、铺满并保持图片比例；主页面自身底色在自定义模式下透明，避免挡住主面板下的图片。侧栏、搜索、列表、按钮、菜单、设置、推荐卡片与播放器使用现有主题变量联动；浮动菜单仍保留不透明有色底，保证操作项容易读。没有模糊滤镜、动态壁纸、背景轮播或常驻分析循环。

补修「我喜欢」与「本地下载」未透出图片的问题：音乐库、音乐库内部 main、本地音乐及下载管理使用独立页面容器，旧的不透明背景覆盖了主面板。自定义模式下将这些页面画布设为透明，共享窗口原有图片与主面板有色遮罩；普通浅深色样式继续使用原底色，表头和操作控件保留清晰的有色底。仅改 CSS，没有增加图片副本或新的运行逻辑。

图片通过已有 getThemes 返回的数据目录保存到 `LxDatas/theme_images/custom-backgrounds/`，测试版位于 `artifacts/user-test-data/` 内对应目录，安装版跟随应用用户数据目录。保留优化后的背景副本，文件名按内容哈希生成；原上传图片不会被移动、改写或删除。保存小型 current.json 配色与尺寸记录，重启直接读取，不重新解码取色。写入先保存临时文件再替换正式记录，写入失败保留原背景；损坏或缺失记录回退普通配色，并提供重新上传入口。仅整理本功能生成的副本，最多保留当前和上一张；不清理原图及其他主题文件。

导入限制为 32 MiB、约 4000 万像素，常见图片的尺寸在解码前检查，手机 JPEG 的 EXIF 旋转参与缩放。保存版本不放大小图，最长边 2560px、面积上限 2560×1440，使用 WebP 质量 0.86。图片数据不写入 localStorage，也不上传网络。导入完成或失败后关闭 ImageBitmap、清空临时 Canvas；取色仅在用户导入时进行。

## 内存控制

自定义背景新增一张受尺寸限制的本地图片；这是用户要求的图片资源，原有音乐封面能力保留。不新增应用运行依赖、后台常驻定时器、后台轮询、图表库、视频或字体资源。分类弹窗按用户动态效果要求增加一个 128×128 的字符粒子 Canvas，最多 320 个粒子，像素倍率上限 1.5；仅在打开、切换和鼠标交互时绘制，最后一次交互后 850ms 停止。关闭时取消 animation frame、移除事件监听并释放粒子；窗口隐藏时停止绘制，尊重减少动态效果的系统偏好。
新增的最近播放与推荐页 Vue 监听随所属组件销毁停止。创建歌单、分类、评论及歌曲操作与播放列表内容按需挂载；最近播放主页面按需挂载。时段更新计时器和平台请求截止计时器均在推荐页离开时清理。
保留现有封面懒加载、128 条 / 8 MiB 有界封面缓存、本地音乐分页、路由及音频按需加载。
推荐封面使用原有图片能力，最多显示少量歌单与歌曲，不复制音频资源。

样式资源体积随构建更新；文件体积不能代表运行时内存增量。
Electron 的主进程、渲染、GPU 和辅助进程分配会波动；本轮不根据单次进程采样承诺固定内存上限或稳定降幅。

## 搜索结果页面与歌手相关性

搜索结果页移除占用首屏的大型介绍、装饰图标和重复输入框，保留顶栏唯一搜索入口；顶栏随搜索路由同步关键词。页面以实际关键词为标题，歌曲 / 专辑 / 歌手 / 歌单使用紧凑下划线导航，右侧选择平台。列表沿用背景和自动配色，歌曲名称为主要文字，专辑为次要文字，歌手独立列出；加载期间显示静态骨架，不逐个平台闪烁追加。

原歌手结果直接拼接所有平台的模糊搜索列表，又将平台总数相加，导致搜索完整姓名也出现无关人物，并显示不准确的跨平台人数。本轮仅在前端增加姓名相关性处理：全角、大小写及多余空格归一；存在完整姓名匹配时仅展示完整匹配；没有完整匹配时按完整输入子串匹配，拉丁文字从单词边界匹配。不做单字拆散匹配，不补入无关人物。按 source + id 去掉重复记录，同名结果分组但保留全部平台/ID 入口，不据此宣称是同一真实人物，也不丢弃同平台同名不同 ID。无关结果被过滤后不会继续显示接口总数；部分匹配显示本页分组数，保留原搜索分页。完整匹配收起无意义的模糊结果分页。

歌手卡使用真实圆形头像、姓名和平台按钮。唯一完整姓名分组会自动读取一个有作品信息的平台目录，并在资料卡下显示歌曲，自动读取不触发播放。平台按钮切换原目录接口，选中状态与实际来源一致。部分姓名查询由用户主动选择歌手；未匹配时显示空态。匹配依据限于平台返回的姓名字段；平台没有提供的别名、拼音、译名不做猜测，需要改用其目录中的姓名搜索。
