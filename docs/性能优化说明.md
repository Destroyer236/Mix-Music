# LinkLine 性能优化说明

本文描述 LinkLine 1.0.6 的资源优化与本次测试口径。

## 资源预算

| 资源 | 当前预算与行为 |
| --- | --- |
| 主界面 V8 | 旧生代上限 512 MiB；本次 Electron 运行时实际报告的总堆上限约 608 MiB |
| 数据库 Worker V8 | 独立旧生代上限 512 MiB |
| 数据库歌单缓存 | LRU，累计不超过 10,000 首、估算 16 MiB 或 32 个歌单；先达到的预算生效 |
| 封面地址缓存 | LRU，最多 128 条或 8 MiB 地址字符串预算；先达到的预算生效 |

V8 的旧生代预算仅约束对应 JavaScript 堆的一部分。总堆还包括新生代等区域；音频解码、图片解码、GPU、原生模块、共享内存和其他进程均不包含在旧生代预算里。因此这里的 **512 MiB 不等于 LinkLine 总运行内存上限**。

歌单缓存预算控制已读取资料的驻留，不限制音乐库或一次导入的歌曲数量。超出预算的歌单仍完整读取与返回，之后需要时再从数据库加载。封面预算仅控制地址记录的保留，浏览器图片解码与显存占用另行计算。

## 按需加载

- 默认系统音频输出且未开启「设备变化时暂停」时，不枚举设备或监听 `devicechange`，避免仅听歌就启动 Chromium 的设备发现服务。具体输出设备、移除暂停和声音设置需要时再加载。
- 设备同步与开放接口未开启时，不加载对应服务树；禁用状态下打开设置也不主动查询同步服务。
- 下载 Worker 和非必要工作线程按实际任务需要创建；下一首预加载、封面请求等资源保持有界保留并清理失败状态。
- 关闭 Chromium 的浏览器后台网络、组件自动更新、扩展、浏览器同步、投屏与自动填充服务器通信。平台音乐请求、网页登录 Cookie、音频播放和 LinkLine 自己的更新检查继续运行。
- 主窗口与歌词窗口关闭不需要的 WebGL、WebSQL 和拼写检查；平台网页登录窗口保留其登录所需能力。

硬件加速默认开启。「设置 → 常规与外观 → 关闭硬件加速」可切换为软件渲染，保存后通过提示完整重启 LinkLine。软件渲染的 GPU 内存可能较低，但 CPU、画面流畅度和总内存效果取决于设备，不能保证每台机器都会更省内存。

## 测量口径与本次样本

以下是前期 Windows 测试机、空闲状态下所有 LinkLine 相关进程合计的样本。它们用于比较本轮改动，不代表各设备的固定运行占用，也不是长时间播放或大型音乐库的峰值。

| 场景 | 合计私有内存（约） |
| --- | --- |
| 优化前 | 646 MiB |
| 优化后，硬件加速开启 | 575 MiB |
| 优化后，硬件加速关闭 | 271 MiB |

打包后的 1.0.6 另做了实际 WAV 播放测试，并开启桌面歌词验证操作。以下数据来自 `release-1.0.6-runtime-ui.json`，将各进程 `privateBytes` 的 KiB 值相加，再除以 1024 得到 MiB。页面、播放和窗口状态与上面的前期空闲测试不同，**两组数据不能直接用于比较优化幅度**。

| 打包版测试场景 | 合计私有内存（约） | 其中 GPU 进程私有内存（约） |
| --- | --- | --- |
| 硬件加速开启，实际 WAV 播放 | 787 MiB | 459 MiB |
| 硬件加速开启，播放并打开桌面歌词 | 841 MiB | 459 MiB |
| 硬件加速关闭，实际 WAV 播放 | 356 MiB | 38 MiB |

本机硬件加速播放样本中，GPU 进程占总私有内存的一半以上；桌面歌词还增加一个界面进程。软件渲染样本较低，只说明这台测试机及当时状态的结果，不保证其他显卡、驱动、歌曲格式或运行时长下得到同样占用，也不是软件承诺的固定内存值。

`privateBytes` 表示进程私有的已提交内存，可能位于物理内存或分页文件中；工作集（`workingSetSize`，WS）表示当时驻留在物理内存中的页面，可能包含共享页面。**两个指标不可混作同一个「内存占用」数值**，也不应把工作集直接与 V8 堆预算比较。多个进程的工作集相加还可能重复计算共享页面。

测量时应记录版本、加速状态、数据目录、窗口与歌词状态、歌曲数量、页面、运行时长以及统计口径。在线封面、平台登录窗口、音效、当前播放和系统缓存都会改变结果。若要排查持续增长，应在同一使用过程连续采样，而不是仅比较两张任务管理器截图。
